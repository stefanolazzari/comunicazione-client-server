Dispensa: Gestione Sistemi e Comunicazione Client-Server

1. Concetti Generali

Server: computer o programma che fornisce servizi, risorse o dati a client.

Comunicazione Client-Server: il client invia richieste; il server risponde con dati o azioni.

Richiesta HTTP: messaggio inviato dal client per ottenere una risorsa o eseguire un'azione.

HTTP Status Codes:

  • 2xx — Successo (es. 200 OK)
  • 3xx — Reindirizzamenti (es. 301 Moved Permanently)
  • 4xx — Errori lato client (es. 404 Not Found)
  • 5xx — Errori lato server (es. 500 Internal Server Error)

localhost: indica il computer locale, indirizzo IP 127.0.0.1.

Web server: software che gestisce richieste HTTP e serve contenuti web.

2. Node.js e Sviluppo Back-end

Node.js: runtime JavaScript lato server basato su V8 (motore di Chrome). Permette di usare JS per creare server, API e script di sistema.

Uso del terminale

node nomefile.js

console.log

console.log('Messaggio di debug');

Differenze: JS in Browser vs Node.js

  • Browser: accesso al DOM, esecuzione dentro pagina HTML, uso di <script>.
  • Node.js: accesso a filesystem, rete, processi; moduli CommonJS / ESM.

npm e package.json

npm init -y
npm install express
cat package.json

Avvio e Chiusura di un server (HTTP nativo)

const http = require('http');

const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Server attivo');
});

server.listen(3000, () => console.log('Server avviato su http://localhost:3000'));
// Per terminare: CTRL + C

3. Express.js

Express è un framework minimalista per creare server e API in Node.js con rotte, middleware e gestione semplificata delle richieste.

Installazione

npm install express
# oppure
npm i express

Creazione delle rotte ed esempio minimo

const express = require('express');
const app = express();

app.use(express.json()); // abilita parsing JSON per POST

app.get('/', (req, res) => {
  res.send('Home Page');
});

app.post('/invia', (req, res) => {
  const body = req.body;
  res.json({ received: body });
});

app.listen(3000, () => console.log('Express su http://localhost:3000'));

Metodi principali

  • app.get() — recupero risorse
  • app.post() — invio dati (creazione)
  • app.put(), app.delete(), ecc.

Creazione delle rotte (route handlers)

app.get('/api/users/:id', (req, res) => {
  const { id } = req.params;
  res.json({ id, name: 'Mario' });
});

4. Client Web

Ruolo di index.html: file principale caricato dal browser; punto d'ingresso dell'app client.

Uso di JavaScript nel client

È possibile includere JS con il tag <script> inline o esterno. Differenze:

  • Tag inline: comodo per snippet rapidi ma meno manutenibile.
  • Script esterno: mantiene separazione tra markup e logica.

fetch()

// richiesta GET
fetch('/api/dati')
  .then(res => {
    if(!res.ok) throw new Error(res.status);
    return res.json();
  })
  .then(data => console.log(data))
  .catch(err => console.error(err));

Funzioni asincrone

async function getDati(){
  try{
    const res = await fetch('/api/dati');
    if(!res.ok) throw new Error('HTTP ' + res.status);
    const json = await res.json();
    console.log(json);
  } catch(e){
    console.error(e);
  }
}

5. API e Servizi Esterni

Definizione di API: Application Programming Interface — interfaccia che consente a sistemi diversi di comunicare e scambiare dati.

Open-Meteo API (esempio)

Open-Meteo fornisce previsioni meteo tramite chiamate HTTP. Esempio di fetch:

fetch('https://api.open-meteo.com/v1/forecast?latitude=45&longitude=9&hourly=temperature_2m')
  .then(res => res.json())
  .then(data => console.log(data));

Nota: verificare parametri (latitude, longitude, timezone, hourly, daily) nella documentazione ufficiale del servizio.

6. Documentazione e Buone Pratiche

readme.md

File Markdown che descrive il progetto: scopo, setup, comandi utili, dipendenze e informazioni per sviluppatori.

Convenzioni utili

  • Usare npm run per comandi di sviluppo (es. npm run start, npm run dev).
  • Documentare le rotte principali e gli esempi d'uso dell'API nel README.
  • Tenere package.json aggiornato e non committare node_modules.
Se vuoi, posso generare anche un file ZIP con un progetto d'esempio o una versione Markdown della dispensa.
